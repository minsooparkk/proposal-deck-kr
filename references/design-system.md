# 디자인 시스템

제안서·보고서가 공유하는 기본 블루·Pretendard 양식이다. 사용자 지정 양식이나 최신 수정본이 우선이다. 새 제안서는 `assets/proposal-template.pptx`, 새 보고서는 `assets/report-template.pptx`의 장 유형을 사본으로 재사용한다. 아래 도구 좌표는 기존 빌더의 참고값이며 원형의 실제 배치를 확인한다. 로고·색만 가져와 새 양식을 만드는 것으로 대체하지 않는다.

법인명·로고·연락처·담당자·색은 `assets/firm.json`(예시: `assets/firm.example.json`)에서 읽는다. 설정이 없으면 `○○회계법인` 같은 자리표시로 만든다.

## 캔버스·그리드

- 16:9, 13.333 × 7.5 in. 좌우 여백 `L = 0.75`, 본문 폭 `CW = 11.833`.
- 내용 장 헤더 참고값: 라벨 y 0.55 (11pt Bold, blue) / 제목 y 0.85 (26pt Bold, ink) / 필요한 설명 y 1.52 (제안서 15pt, 보고서 원형 14pt). 새 목차·보수표 등에 부제를 강제로 추가하지 않되, 기존 헤드메시지·요약 설명문은 보존한다. 서식 통일이나 공간 확보를 이유로 기존 설명문을 삭제하지 않는다.
- 본문 영역 참고값: y 2.3 ~ 6.75. 하단 강조 밴드는 필요한 페이지에서만 원형의 배치를 따른다. 삭제된 박스를 기본 좌표가 있다는 이유로 추가하지 않는다.
- Footer: 왼쪽 법인명(설정 `firm_name`), 오른쪽 두 자리 페이지 번호(9.5pt). 간지는 번호만.
- 카드 사이 간격 0.3 in(FAQ처럼 6칸이면 0.25). 카드 내부 여백 0.3~0.4 in.

## 글꼴

- 모든 run과 테마 major/minor/Hang을 Pretendard로 지정(`font_run`이 latin·ea·cs 모두 설정).
- 검수에서 정한 기준: 표지·간지 제목 46pt, 법인명 15pt, 로고 0.42in으로 같은 역할의 요소를 통일했다. 간지 번호는 54pt, 내용 제목은 26pt, 카드 제목은 17~20pt, 본문은 13~15pt, 주석은 10~11pt가 기존 양식의 기준이다. 새 양식은 실제 배치와 가독성을 우선한다. 제목·법인명·로고를 서로 같은 크기로 만들라는 뜻은 아니다.
- '前' 같은 한자는 Pretendard에 없으므로 해당 글자만 맑은 고딕 run으로 나눈다(`deck_lib.HAN`, `sections._with_han`).

## 장 유형 (재사용 우선)

| 유형 | 구현 | 쓰는 곳 |
|---|---|---|
| 표지 | `cover(eyebrow, title, sub_runs)` | 주제를 드러내는 제목 중심. 부제·강조 문구는 필요할 때만 |
| 목차 | `contents([(번호, 장명, 시작 쪽)])` | 장 번호·장명·시작 쪽수 하나 |
| 간지 | `divider('01', '섹션명', [])` | 섹션마다. 소제목 목록은 비움 |
| 3칸 문제 카드 | surface 카드 + 상단 blue 7px 바 + 번호 + 제목 + 회색 한 줄 + 체크 목록 | 고객이 겪는 어려움, 단계별 과제 |
| 2×2 카드 | 좌측 blue 세로 바 + 제목 + 설명 | 검토 영역 네 가지 |
| 4단계 로드맵 | 머리 박스(dark, 마지막만 blue) + 번호 목록 + 사이 화살표 | 단계별 검토 사항 |
| 비교표 | `table()` 네이티브 표, 머리글 dark | 업무 수행 방식 / 검토상 한계 / 영향, 범위표 |
| 질문 카드 | Q 카드 + 하단 dark 답 박스 | 고객이 확인할 질문(비교 광고 대신) |
| 두 숫자 대비 | 좌 surface / 우 dark 카드 + 아래 3행 설명 | 전체 규모와 원칙 한도처럼 성격이 다른 두 수치 |
| 소통 구조도 | 고객 → 담당 회계사(dark) → 전문가 3칸 + 4단계 흐름 | 직접 응대 원칙 |
| 인물 카드 | 역할 라벨 + 이름 22~24pt + 직함 + 약력 + pale "업무 범위" 박스 | 연계 전문가, 전문위원 |

같은 유형을 반복해 지루해지거나 정보 위계가 흐려지지 않는지 확인한다. 항목이 두 줄이어도 의미와 읽기 흐름이 명확하면 허용한다. 줄 수를 맞추려고 중요한 조건을 지우지 않는다.

## 정렬·줄바꿈·강조

일반 기준은 [공통 편집 규칙](editing-rules.md)을 따른다. 목차는 장 번호·장명·실제 쪽수로 구성하고 항목별 부제를 기본적으로 넣지 않는다. 아래는 기존 도식·원형의 보조 기준이다.

- 단계 제목과 짧은 대상 고객 문구는 해당 영역 안에서 가운데 정렬할 수 있다. 제목의 가운데 정렬 요청을 긴 본문 전체로 확대하지 않는다.
- `검/토`처럼 한 단어가 음절로 갈라지지 않도록 의미 단위로 나눈다. 같은 항목 안에서는 Shift+Enter에 해당하는 수동 줄바꿈을 활용하고, 문단·글머리표를 불필요하게 새로 만들지 않는다.
- 문구 정리와 상자 폭·높이 조정을 먼저 고려한다. 폰트 축소는 가독성을 유지하는 범위에서 마지막에 검토한다. 실제로 한 줄에 자연스럽게 들어가는 문장에는 수동 줄바꿈을 남기지 않는다. 중요한 조건을 지우거나 글꼴을 과도하게 줄여 한 줄로 만들지는 않는다.
- 하단 강조 문구는 무엇을 말하는지 독립적으로 이해되어야 한다. 사용자가 결론 강조를 지정한 경우 본문 폭의 옅은 청색 밴드 안에 핵심 문장을 가로·세로 가운데 배치할 수 있다. 일반 본문까지 가운데 정렬하지 않는다. 이미 설명한 수행 약속을 모든 페이지 끝에 반복하지 않으며, 사용자가 삭제한 하단 문구를 빈 공간을 채우려고 복원하지 않는다.
- 웹사이트·이메일은 페이지 목적에 필요하지 않거나 다른 장과 중복되면 생략한다. 포함할 때는 본문보다 낮은 강조 수준의 일반 텍스트로 배치한다. 업무 절차 페이지에 연락처나 진한 파란 박스를 자동 삽입하지 않는다. 연락처가 핵심인 마무리 장은 문맥에 맞게 판단한다.
- 협업 도식은 작성 법인과 협업 전문가의 역할을 중심으로 구성하고 실제 지원 국가·범위는 표로 별도 설명한다.
- 사무소 수의 단위는 `개소`로 통일한다. 인원·고객사·금액에 같은 단위를 적용하지 않는다.

## 역할·인계 흐름 도식

사용자가 주체별 업무 흐름을 박스로 요청한 경우 다음 기준을 적용한다. 모든 서비스 소개서를 박스 중심으로 바꾸는 일반 규칙은 아니다.

- 같은 위계의 주체는 같은 크기·높이의 박스로 맞추고, 상단 주체명과 하단 업무 설명 사이에 얇은 가로 구분선을 둔다. 짧은 주체명과 명사형 업무는 가운데 정렬한다.
- 주체별 설명의 수준과 분량을 맞춘다. 한 주체만 여러 업무를 길게 나열해 박스가 커지지 않도록 핵심 역할을 간결하게 쓴다. 자세한 범위는 해당 업무 설명에서 다룬다.
- 박스 사이의 화살표는 실제 기록·자료·업무의 전달 순서를 나타낸다. 방향과 높이를 통일하고, 직함보다 역할명이 정확하면 역할명을 쓴다. 특정 인원 수·직함·업종을 범용 기본값으로 고정하지 않는다.

## 사진

- 설정 `people[].photo`(세로 2:3, 예: 480×720). 자리표시는 `assets/person_placeholder_a.png`·`_b.png`. 카드 안 2.3 × 3.45 in.
- 두 사진의 머리 크기·위치가 다르면 `people[].crop`(left, top, right, bottom 비율)으로 PowerPoint 자르기를 적용해 맞춘다. 원본 파일은 보존한다.
- 인물 사진을 새로 넣으면 배경 대비로 윤곽(정수리·목·어깨 폭)을 계산해 두 사진의 머리 크기와 정수리 높이를 맞춘다.
- 사진·이름·약력은 본인이 공개에 동의한 것만 쓴다.

## 로고

설정 `logo`(투명 배경 PNG, 정사각). 어두운 배경에서만 쓰고 옆에 법인명 15pt Bold 흰색. 자리표시는 `assets/logo_placeholder.png`.
