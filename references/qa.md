# PPT 검수

## 공통

- 장별 실제 본문 장수를 세어 제목의 진행 번호를 확인한다. 단일 본문 장에는 `(1/1)`을 붙이지 않으며, 여러 본문 장의 `(i/n)`은 간지·목차를 제외한 실제 장수와 일치해야 한다. 하단 전체 페이지 번호는 별도로 유지한다.

- 최신 사용자 요청의 적용·대기·미확정 상태와 실제 파일을 대조한다. 사용자가 삭제한 요소가 다른 페이지나 이전 빌더에서 되살아나지 않았는지 확인한다.
- 원본과 수정본의 제목 아래 헤드메시지·요약 설명문을 장별로 대조하여 요청하지 않은 삭제·축약이 없는지 확인한다. 새 부제를 강제로 추가하지 않는 기준과 기존 설명문을 보존하는 기준을 구분한다.
- [공통 편집 규칙](editing-rules.md)에 따라 짧은 주제 제목, 필요한 설명문, 목차·간지·본문 장명과 쪽수, 표지 수신처를 확인한다. 목차는 범위 없이 시작 쪽수 하나만 표시하며 실제 해당 항목의 시작 쪽수와 일치하는지 확인한다.
- 한 줄로 들어가는 문장의 강제 줄바꿈, 단어 중간 분리, 괄호 부연의 위치와 네이티브 불렛의 이어지는 줄을 실제 크기로 본다. 표는 명사형 항목·설명의 가운데 정렬, 완결된 문장의 왼쪽 정렬, 금액 비교의 오른쪽 정렬을 구별한다.
- 현재 페이지와 무관한 진한색 박스, 과도한 연락처 강조, 근거 없는 회신시간·동일 팀·단기 완료 약속을 추가하지 않았는지 확인한다.
- 자료의 회사·기간·단위·합계·기준일을 대조한다. 서식 편집만으로 사실·법령 재검증을 했다고 표시하지 않는다.
- 표·차트의 공통 단위가 해당 개체 우측 상단에 `(단위: 백만원)` 형식으로 표시되는지 확인한다. 실제 단위와 수치가 일치하고 하단이나 머리글에 단위·반올림 안내가 중복되지 않는지 대조한다.
- 원본의 로고·배경·사진 비율·글꼴·그리드·표·차트·내장 데이터를 보존한다. 새 차트는 새 데이터에 맞게 축·계열·레이블 범위를 확인한다.

## 제안서·서비스 소개서

- 사용자가 직접 수정한 연락처·문구·한 줄 배치·결론 밴드·삭제 항목이 후속 제작에서 보존되는가? 파일에 실제 반영된 사항과 대화 중 추가 요청은 구분했는가?
- 역할 박스를 요청한 경우 같은 크기, 제목·설명 구분선, 균형 있는 문구 길이, 화살표 방향을 확인한다. 단순한 사무용 파일 재저장 차이를 새로운 디자인 선호로 기록하지 않는다.
- 소개서가 유도할 의뢰 범위와 마지막 페이지의 이용 방식이 일치하는가? 외부 검토 의견 때문에 사용자가 정한 수임 목적을 바꾸지 않았는가?

- 앞의 과제마다 실제 수행 내용이 대응하는가? 경력·장점 나열로 설명을 대신하지 않았는가?
- 업무 범위, 지원 국가, 외부 전문가 역할, 전달물·일정·보수 조건이 표·도식·본문에서 일치하는가?
- 법인 전체 실적과 담당자 개인 경험을 구분했는가? 관련 경험은 역량 소개와 연결되는가?
- 일반 제안서의 보수는 공급가액과 공통 VAT 안내로 명확한가? 제출처가 요구한 VAT 포함 총액·세액은 빠뜨리지 않았는가?
- 표시 방식만 바꿀 때 차수별 보수·합계·지급비율을 바꾸지 않았는가?

## 보고서

- [페이지 흐름](report-flow.md)에 따라 제목·핵심 판단을 순서대로 읽고 필수 전제가 분석보다 먼저 등장하는지 확인한다. 아직 안 나온 뒷장의 개념·관계·가정을 먼저 설명해야 하면 순서를 고친다.
- 고객 질문에 현재 판단과 근거가 있는가? 추가 자료 요청만 반복하지 않았는가?
- 사실·전달사항·가정·잠정 계산·제언이 구분되는가? 핵심 계산 조건이 금액 가까이에 보이는가?
- 본문 판단을 반영한 요약이 목차 다음에 있고, 요약·권고가 본문보다 강한 결론으로 바뀌지 않았는가?
- 회사와 개인 귀속, 비교 시나리오, 표시 단위와 원자료 정밀도를 유지했는가? 산술적 변화를 원인 입증으로 주장하지 않는가?
- 사용자 검토용 형광표시는 작업본에 보존하고, 고객 배포 요청이 있으면 배포 사본에서 정리했는가? 불필요한 고객 정보·작업 이력이 노트·메타데이터에 남지 않았는가?
- 보고서에 제안서의 가격·수행 약속·회사 소개 장을 관성적으로 붙이지 않았는가?

## 렌더링과 전달

최종 전체를 렌더링한다. 소규모 수정은 바뀐 장을 개별 비교하고 전체 덱의 의도치 않은 변화도 확인한다. 원형·마스터를 바꿨으면 영향을 받는 모든 장을 본다. 자동 무결성·넘침 검사만으로 내용과 디자인을 검수했다고 주장하지 않는다.

PowerPoint를 사용할 수 있는 환경에서는 최종 PPTX를 실제로 열어 복구 경고가 없는지 확인하고, 차트가 있는 모든 장을 렌더링해 개체와 데이터가 유지되는지 확인한다. Open XML 검증기를 사용할 수 있으면 차트 축 참조와 요소 순서 오류도 확인한다. 복구 경고나 차트 누락이 있으면 원인을 고친 새 사본으로 다시 검수한다.

Pretendard와 필요한 한자 대체 글꼴이 실제 렌더링에 사용되는지 확인한다. `前`이 □로 표시되면 해당 글자만 원본의 대체 글꼴을 유지한다. 문자 수로 만든 대략적 한 줄 기준보다 최종 화면을 우선한다.

새 버전 PPTX와 요청한 미리보기를 제공한다. PDF는 요청과 도구 지원에 맞춰 내보내며 이미지형 PDF의 제한을 밝힌다. PowerPoint에서 실제 열어 확인했을 때만 PowerPoint 검수라고 설명한다. 수정 설명은 짧은 `Before → After`로 실제 반영사항만 적는다.
