# 사용자 검토본에서 확정한 보고서 편집 원칙

사용자가 직접 수정한 보고서에서 추출한 보고서 모드 전용 기준이다. 수정본의 고객별 수치·법적 판단·미확인 사실은 다른 업무의 기본값이 아니다. 이후 공통 편집 리뷰는 [공통 편집 규칙](editing-rules.md), 설명 순서는 [페이지 흐름](report-flow.md)에 반영되어 있다. 제안서의 보수 페이지에 보고서용 결론 부제나 요약 간지를 강제로 넣지 않는다.

## 전달 방식

고객 앞에서 회계사가 설명할 수 있는 자료를 만든다. 각 페이지는 핵심 판단 하나와 근거 표 하나를 중심으로 구성한다. 세부 예외와 내부 검토 이력을 모두 슬라이드에 담아 읽기 자료처럼 만들지 않는다. 면담용의 20쪽 안팎은 과거 작업의 분량 참고값이며 현재 요청과 설명에 필요한 길이를 우선한다.

순서는 표지, 목차, Executive Summary 간지, 핵심 요약, 장별 간지·본문, 실행 과제, Thank You이다. 새로운 지시 없이 순서를 바꾸거나 요약을 목차 앞으로 이동하지 않는다. 불필요한 Appendix를 자동 생성하지 않는다.

## 제목·표·권고는 서로 다른 문장 역할을 갖는다

| 위치 | 작성 기준 | 예시 |
|---|---|---|
| 본문 제목 | 장명·번호·주제 유지 | `승계 계획 검토(1/3) - 개요` |
| 분석 페이지의 제목 아래 설명 | 완결된 한 문장으로 결론·조건 표시 | `현재 자료에 기초할 때 적용 가능성이 높은 것으로 판단됩니다.` |
| 표의 요건·판단 | 명사형·짧은 구절 허용 | `요건 충족`, `5년으로 연장`, `추가 확인 필요` |
| 고객에게 제시할 권고 | 선택할 행동을 직접 제시 | `단기예금 운용을 권장드립니다.` |
| 잠정 계산 결과 | 간결하되 확정 수준 유지 | `현재 가정에서는 약 [금액]으로 추정됩니다.` |
| 표 아래 강조 | 판단 하나, 필요하면 핵심 조건과 결합 | `[핵심 가정] 적용 시 [결과]로 추정됩니다.` |

`~을 우선 비교하는 것이 적절합니다`처럼 검토 절차만 말하는 문장은, 추천할 근거가 충분하면 구체적인 권고로 바꾼다. 근거가 부족한 경우까지 결론을 확정하는 규칙은 아니다. 이미 확인된 사실과 실제 남은 증빙을 구분해 쓴다.

표에 간결한 종결을 쓰는 것과 부제의 문장을 중간에서 끊는 것은 다르다. 모든 표 셀에 긴 설명·존댓말을 반복하거나, 모든 제목을 긴 결론 문장으로 통일하지 않는다.

## 표와 숫자

- 기본은 편집 가능한 네이티브 표다. 진한 남색 머리글, 옅은 교차 행, 승인된 여백·열 폭을 유지한다.
- 짧은 요건·비교값은 가로·세로 가운데 정렬이 적합하다. 긴 설명과 산식은 왼쪽 정렬을 유지한다. 사용자 수정본도 요건표만 가운데로 바꾸고 산식·긴 문장표는 왼쪽 정렬을 유지했다.
- 억원 금액은 보통 소수점 두 자리로 표시한다. 결과의 정밀도가 의사결정에 필요할 때만 자리수를 늘린다. 원·만원·비율·주식 수까지 일괄 두 자리로 바꾸지 않는다.
- 계산은 반올림 전 원자료로 수행한다. 표시용으로 반올림한 입력을 다시 계산에 사용하지 않는다. 단위는 [공통 편집 규칙](editing-rules.md)에 따라 표·차트 우측 상단에 표시하고 `반올림`·`절사` 설명을 붙이지 않는다. 재계산 차이의 근거는 검산 자료에 보존한다.
- 계산 과정은 `단계 / 산식 / 결과`의 세 열로 정리한다. 최종 결과 행은 청색·굵은 글씨로 강조한다.
- 한 줄에 들어가는 산식을 불필요하게 두 줄로 쪼개지 않는다. 숫자와 단위, 한 의미 단위가 떨어지지 않게 줄바꿈한다.

## 각주·중복·여백

긴 출처·예외·검토 경과를 매쪽 하단에 반복하지 않는다. 기본은 각주 없이 읽히는 본문이며 꼭 필요한 경우만 짧은 조건을 둔다. 수정본에서 일부 각주는 유지됐으므로 모든 각주를 없애는 규칙으로 해석하지 않는다.

1. 표·부제에 이미 있는 설명은 반복하지 않는다.
2. 예상세액의 재산 범위나 핵심 계산 가정처럼 결론을 바꾸는 조건은 부제·표의 행명·금액 옆에 짧게 표시한다.
3. 조문 전문, 상세 출처, 제외한 비용, 검산 파일, 내부 변경 기록은 별도 근거 자료에 보존한다. 고객용 PPT의 숨은 노트에 작업 이력을 쌓지 않는다.
4. 표 아래 여백이 생겨도 자동으로 문장·박스·각주를 채우지 않는다.
5. 사용자가 삭제한 문구는 이전 빌더 실행으로 되살리지 않는다. 내용 정확성에 영향을 주는 삭제는 별도 대조 기록에 남기고 최소 표현으로 해결한다.

## 시각적 세부 기준

- 기본 블루·Pretendard·16:9·좌우 0.75인치·본문 제목 26pt·설명 14pt를 유지한다. 글을 줄이지 않고 글꼴을 작게 만드는 방식으로 맞추지 않는다.
- Executive Summary 간지는 `ES` 약자와 별도 제목을 중복 배치하지 않고, 큰 청색 `Executive Summary` 표제 하나로 구성한다. 현재 틀은 54pt 두 줄이며 텍스트 상자 높이도 실제 두 줄을 수용한다.
- 본문 장 간지는 기존의 장 번호·흰색 장 제목 체계를 유지한다. 요약 간지의 디자인을 모든 장에 일괄 적용하지 않는다.
- 핵심 결론은 기존 청색 굵은 문장 또는 옅은 파란 강조 띠 한 개로 표시한다. 강조 띠는 가운데 정렬·굵은 글씨이며 여러 카드로 나누지 않는다.
- 후속 피드백으로 노란 형광표시가 공부할 항목 표시임을 확인했다. 사용자의 공부·검토용 작업본에는 보존하고, 고객 배포용 PDF를 만들 때 별도 사본에서 제거한다. 고객에게 PPT도 제공할 경우 그 배포 사본 역시 정리한다. 중립적 틀에는 넣지 않는다.

## 재사용할 때 학습하지 않을 것

- 고객명, 주주·가족 관계, 실제 금액, 특정 세율·법령 요건·확정되지 않은 판단.
- `영업이익`과 `순이익`처럼 계산 지표의 의미가 달라진 문구를 단순 표현 교체로 취급하는 것.
- 과세 이연을 영구 절세로 바꾸거나 회사 자금 증가를 개인 가처분소득 증가로 바꾸는 것.
- 단일 슬라이드의 편집 누락·문법 오류·PowerPoint의 run 분절을 새로운 스타일 규칙으로 받아들이는 것.
- 검토본의 형광표시를 최종 납품용 강조색으로 고정하는 것.

원본을 다시 작성하라는 지시 없이 사용자 수정 PPT 자체를 고치지 않는다. 후속 작업은 최신 사용자 수정본을 시작점으로 하며, 이전 생성 스크립트로 덮어쓰지 않는다.
