# PPT 공통 편집 기준

제안서·서비스 소개서·보고서의 문구와 배치에 적용한다. 사용자와 확정한 최신 수정본이 우선한다. 아래 기준은 특정 문서의 페이지 수·금액·인력·수행 약속을 다른 문서에 복제하는 규칙이 아니다.

## 제목·설명·목차

- 장 안의 본문이 한 장이면 제목에 진행 번호를 붙이지 않는다. 예: `사업 현황(1/1) - 수익과 비용` → `사업 현황 - 수익과 비용`. 같은 장의 본문이 두 장 이상일 때만 `장명(i/n) - 세부 주제`로 표기한다. `n`은 간지·목차를 제외한 해당 장의 실제 본문 장수이며, 분량 변경 시 다시 계산한다. 이 규칙은 하단의 전체 페이지 번호와 목차 시작 쪽수에는 영향을 주지 않는다.

- 큰 제목은 페이지의 주제를 드러내는 짧은 명사구를 기본으로 한다. 문장형 제목의 어미만 자르지 말고 실제 주제를 다시 정한다. 수행 약속·성과 수치를 제목으로 자동 승격하지 않는다. 사용자가 지정한 결론형 제목은 따른다.
- 기존 문서를 수정할 때 제목 아래의 헤드메시지·요약 설명문은 보존한다. 본문·표·숫자와 겹친다거나 없어도 이해된다는 판단만으로 삭제하지 않는다. 설명문 삭제·축약은 사용자가 요청한 범위에서만 반영하며, 서식 통일·단위·목차 수정에 임의로 포함하지 않는다.
- 새 장을 작성할 때는 필요한 이유·조건·판단을 전달하는 설명문을 선택해 둔다. 목차·보수표 등이 자체로 이해되면 새 부제를 강제로 추가하지 않는다. 이 신규 작성 기준을 기존 설명문을 지우는 근거로 사용하지 않는다.
- 목차는 장 번호·장명·시작 쪽수로 간결하게 구성하고 항목별 부제는 기본적으로 넣지 않는다. 쪽수는 해당 항목의 시작 쪽수 하나만 표시한다(예: `5–7` → `5`). `5-7`, `5~7`처럼 끝 쪽수를 붙인 범위 표기는 사용하지 않는다. 페이지 이동 후에는 실제 시작 쪽수와 다시 맞춘다.
- 새 문구에는 한국어 제목과 같은 뜻의 영문 라벨, 본문을 반복하는 상투적인 소개문, `별도 견적서에 기재하였습니다` 같은 불필요한 안내를 추가하지 않는다. 기존 요소의 정리는 요청 범위를 따르며, 헤드메시지·중요한 조건·지정양식의 필수 문구를 임의로 삭제하지 않는다.
- 앞으로 수행할 용역은 자연스럽게 `~할 예정입니다`로 쓴다. 확인 사실·금액·현재 범위·이미 수행한 검토는 그 의미에 맞는 시제를 유지한다.
- 표지에 수신처가 필요하면 기관명·고객명만 간결하게 적는다. 별도 요청이 없으면 `귀중` 뒤에 담당자·직책·기간 등을 나열한 메타정보 블록을 만들지 않는다.

## 줄바꿈·목록·표

- `취/합`, `인정금/액`처럼 단어 중간에서 끊기지 않게 한다. 상자 폭·열 너비·문구를 먼저 조정하고 필요한 곳에만 의미 단위의 수동 줄바꿈을 넣는다. 한 줄로 자연스럽게 들어가면 강제 줄바꿈을 남기지 않는다. 특히 넓은 설명 밴드의 한 문장은 문구를 간결히 하고 내부 폭을 활용해 불필요한 두 줄 배치를 피한다. 한 줄을 만들려고 본문 글자를 줄이거나 모든 문장의 줄 수를 고정하지 않는다.
- 같은 항목의 이어지는 줄은 새 문단·새 불렛으로 만들지 않는다. 목록은 네이티브 글머리표와 내어쓰기를 사용해 두 번째 줄이 본문 시작점에 맞도록 한다. 단계별 카드 안의 병렬 항목도 이 기준을 적용한다.
- 수행 업무명 뒤의 괄호가 기관·연도 등 보조정보이고 줄을 나눠야 한다면 `(` 앞에서 나눈다. 짧은 괄호 표현을 모두 새 줄로 보내지는 않는다.
- 표 머리글과 문장이 아닌 명사형 항목·설명은 길이에 관계없이 가운데 정렬한다. 완결된 설명 문장은 왼쪽 정렬하며, 합계를 비교하는 금액·수치는 오른쪽 정렬을 고려한다. 셀의 세로 정렬도 함께 확인한다. 긴 명사구라는 이유만으로 왼쪽 정렬하지 않는다.
- 한글 단어 단위 줄바꿈 설정만으로 완료했다고 보지 않는다. 실제 PowerPoint 또는 최종 렌더링에서 단어 분리·자동 줄바꿈·넘침을 확인한다. 글자 크기 축소는 폭·내용 조정 후 검토한다.

## 표·차트 단위 표기

- 공통 단위는 해당 표·차트 바로 위 우측 끝에 맞추어 `(단위: 백만원)` 형식으로 간결하게 표시한다. 실제 수치에 따라 `(단위: 원)`, `(단위: 억원)`, `(단위: 시간)` 등으로 적으며 백만원으로 일괄 환산하지 않는다. 공통 단위가 없는 설명표에 임의의 단위를 붙이지 않는다.
- 단위 표기에는 단위만 넣고 `반올림`·`절사`·출처·기준일을 덧붙이지 않는다. 아래쪽의 `백만원 반올림`, `백만 원 미만 반올림` 같은 설명은 제거하고 머리글에만 있던 공통 단위도 우측 상단으로 옮긴다. 필요한 출처·기준일·수행 조건은 단위와 분리하여 보존한다.
- 단위 위치를 바꿀 때 원자료, 표시 금액, 소수 자릿수, 계산 정밀도를 바꾸지 않는다. 계산은 반올림 전 값으로 수행하며 검산 근거는 별도로 관리한다.

## 강조 박스와 정보 배치

- 사용자가 병렬 업무 박스의 제목과 짧은 명사형 목록을 가운데 정렬한 경우 그 배치를 후속 편집에서도 유지한다. 여러 업무는 간결한 목록으로 구분하며, 사용자가 확정한 최종본의 목록 표시를 임의로 되돌리지 않는다. 새 목록을 만드는 경우 네이티브 글머리표를 우선한다. 긴 설명 문장까지 일괄 가운데 정렬하지 않는다.
- 고객용 절차에서 온건한 표현을 요청받으면 내부 수임 행위보다 제공 업무의 연결을 나타내는 말을 검토한다. 예: `기장 인수` → `기장 연계`. 실제 업무 범위·계약 조건을 감추거나 모든 문서의 용어를 기계적으로 교체하지 않는다.

- 진한색 박스는 해당 페이지의 주제와 직접 연결되는 내용만 담는다. 공간을 채우기 위해 홍보 문구나 별도 주제의 장점을 추가하지 않는다. 업무 대응 페이지에서는 실제 소통·검토 절차를 설명한다.
- 회신시간, 동일 팀 유지, 단기 완료 같은 서비스 수준 약속을 기본값으로 추가하지 않는다. 현재 과업에서 승인된 약속이고 독자의 판단에 필요할 때 적절한 위치에 한 번 기재한다. 사용자 삭제 지시가 있으면 다른 페이지로 옮겨 남기지 않는다.
- 제안서의 관련 업무 경험은 수행 절차 중간에 끼워 넣기보다 법인·수행 역량 소개와 연결한다. 법인 전체 실적과 참여 회계사의 개인 경력을 구분한다. 보고서에 법인 소개를 자동 추가하는 규칙은 아니다.

## 제안서 보수 페이지

- 일반 제안서에서는 공급가액을 중심으로 표시하고 공통 안내 `※ 부가세 별도`를 표·가격 카드 아래에 한 번 둔다. 각 카드마다 부가세 포함 금액을 반복하지 않는다. 제출처가 VAT 포함 총액·세액 구분을 요구하거나 사용자가 요청하면 그 기준을 따른다.
- 가격 표기를 바꾸는 것과 계약 금액을 바꾸는 것을 구분한다. 차수별 보수·합계·지급비율은 승인된 수치를 유지하고 합계 관계를 확인한다.
- 행 이름은 의미가 분명하도록 `지급방식`, `포함업무`처럼 적는다. 별도 견적서 안내나 중복 부제 때문에 가격·조건이 흐려지지 않게 한다.

## 리뷰 누적과 적용

- 사용자가 직접 수정한 파일은 전달했던 원본과 별도 사본으로 비교한다. 문구뿐 아니라 수동 줄바꿈·텍스트 상자 폭·정렬·배경·삭제 요소를 확인한다. 저장 과정의 개체명 변경이나 동일한 테두리 속성의 재기록을 사용자 편집 의도로 간주하지 않는다. 실제 변경과 대화로 요청한 미반영 사항을 나누어 기록한다.
- 사용자가 수정한 연락처·문의 경로는 해당 문서의 최신 기준으로 보존한다. 이전 공통 이메일이나 템플릿 값으로 되돌리지 않는다. 개별 연락처 자체를 공용 스킬에 고정하지 않는다.

- `페이지 / 대상 제목 또는 요소 / Before / After / 상태`로 의견을 모은다. 사용자가 일괄 반영을 요청하면 수집 단계에서 파일을 매번 수정하지 않고, 반영 요청이 오면 모은 내용을 적용한다. 즉시 수정 요청은 그 요청을 따른다.
- 페이지 이동 후에는 이전 번호와 현재 번호를 함께 확인한다. 확정된 최신 삭제·수정이 중간 제안보다 우선한다. 다른 페이지로 옮겨서 삭제된 내용을 되살리지 않는다.
- 수정안 설명은 짧은 `Before → After`로 제시한다. 실제 반영사항과 제안·미확정 사항을 구분한다.
- 특정 페이지의 박스 삭제·한 줄 배치·경험 장 이동을 모든 문서의 고정 구조로 만들지 않는다. 원본 파일, 승인 문구·숫자, 편집 가능한 표·차트·내장 데이터는 요청 범위에 맞춰 보존한다.
