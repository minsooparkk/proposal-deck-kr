# 자문 보고서 자료·검토·원고 작업

고객이 결정할 문제에 답하는 자문 보고서를 만든다. 사용자의 최신 합의와 기존 원고를 먼저 읽고 이미 확인한 사실과 승인한 방향을 이어받는다. 특정 고객의 사실·금액·세율·검토 결론을 다른 고객의 기본값으로 재사용하지 않는다.

사용자 직접 수정본에서 정리한 [작성 스타일](user-reviewed-style.md)을 기본으로 한다. 기존 제작 코드보다 사용자 최신 수정 파일을 우선한다. 사용자 수정본에서 스타일을 학습하는 요청은 그 파일을 다시 고치라는 요청과 구분한다.

## 적용 순서

1. **맥락 복원:** 저장된 인수인계, 최신 합의, 자료 목록, 원고, 계산 근거와 검토 회신을 읽는다. 실제 읽은 범위와 미확보 자료를 구분한다. 작업 전 무엇을 할지 짧게 설명한다. 파일 수를 늘리는 것을 진척으로 대신하지 않는다.
2. **질문과 목차 연결:** 고객의 의사결정별로 질문을 정하고 본문 장에 연결한다. 적용 가능성에 대한 판단이 필요한 경우, 현재 자료로 판단한 뒤 계산과 대안을 제시한다. 임의 비율표나 추가 자료 요청만으로 판단을 대신하지 않는다.
3. **주제별 원고:** `현재 판단 → 근거와 계산 → 대안의 유불리 → 결론을 바꾸는 조건 → 조치` 순으로 작성한다. 사용자가 주제별 논의를 원하면 그 순서를 따른다. 이미 받은 이력과 사실을 반복해서 질문하지 않는다.
4. **검토 회신 대조:** 사용자가 맡긴 검토라면 전달문을 작성하고 사용자가 가져온 원문을 보존한다. 쟁점을 반영·수정·미채택·미확정으로 구분한다. 검토자가 쓴 법령 번호나 주장 자체를 확인 증거로 취급하지 않는다. 지적이 기존 원고의 오류인지, 이미 표시한 가정인지부터 확인한다.
5. **통합 원고:** 회사·개인 귀속, 소득 기준, 기간, 단위와 시나리오를 맞춘다. 본문·표·문답·근거표·관리양식을 함께 수정한다. 서로 다른 조건의 결과를 합쳐 절세 총액을 만들지 않는다.
6. **Executive Summary:** 본문 판단을 정리한 다음 마지막에 작성한다. 배치는 **`표지 → 목차 → Executive Summary 간지 → 핵심 요약 → 장별 간지·본문 → 실행 과제 → Thank You`**로 한다. 요약을 목차 앞에 놓으라는 과거 지침은 폐기한다. 별도 Appendix는 자동으로 붙이지 않고 필요한 내용은 본문에 압축한다. 사용자가 특정 납품물에 다른 순서를 요청하면 그 지시를 따른다.
7. **PPT와 검수:** [이 스킬의 SKILL.md](../SKILL.md)와 원형을 읽고 원본 사본에서 제작한다. 전체를 렌더링하고 본문·표·차트·각주·목차를 실제로 확인한다. 발표자 노트만으로 핵심 계산 조건을 표시하지 않는다.
8. **저장과 인수인계:** 수정 이유, 근거, 검수 범위, 남은 결정과 최신 산출물 위치를 남긴다. 파일 저장·커밋·원격 동기화·고객 발송을 구분한다. 보고서 작성 승인에서 외부 전송 권한을 추정하지 않는다.

## Executive Summary의 내용

보통 한두 장에서 주요 판단 4~6개와 우선 조치를 보여준다. 장 제목을 나열하는 목차나 보고서의 목적 설명으로 대신하지 않는다.

각 판단에는 필요한 만큼 다음 내용을 넣는다.

- **현재 결론:** 고객이 기본안으로 삼거나 비교해야 할 선택.
- **의미 있는 근거:** 결론을 뒷받침하는 핵심 사실이나 금액. 자료 기간·재산 범위·귀속이 필요한 숫자에는 함께 표시.
- **결정 조건:** 실제 결론을 바꾸는 조건 한두 가지. 모두 나열하지 말고 상세 본문에 연결.
- **다음 조치:** 누가 무엇을 정리하거나 결정해야 하는지.

정책 변경이 권고를 바꿀 수 있으면 요약에도 표시한다. 조건부 계산의0원, 회사에 남는 현금, 이월공제, 신고 환급과 신규 확정 절세액을 같은 성격으로 쓰지 않는다. 요약에서 권고를 본문보다 강하게 바꾸지 않는다.

## 수치와 법령의 연결

- 확인 사실, 전달된 이력, 추정, 설명용 계산과 미확인 사항을 구분한다.
- 비교 시나리오에는 공통 입력과 달라진 입력을 적는다. 한 사람이 받는 여러 사업의 소득은 동일 기준으로 합산해 계산하고 원천징수·공제를 중복 차감하지 않는다.
- 법령 현행 조문, 과거 적용례, 시행예정 조문, 정부 발표안과 기사 해설을 구분한다. 최신 개정일만으로 모든 항목의 최초 적용연도를 판단하지 않는다.
- 원문 조회가 잘렸거나 검색 결과가 다른 사건이면 전문 확인 완료로 기록하지 않는다. 확보 가능한 분석을 진행하면서 구체적인 미확보 부분만 후속 목록에 남긴다.
- 법적 결론이 달라지는 수정은 원 계산부터 고친 뒤 원고·요약·PPT·문답으로 전파한다. 표시만 보완한 경우 계산값을 변경했다고 설명하지 않는다.

## 제작 검수에서 배운 점

- 본문 제목은 장명·번호·세부 주제를 유지하고, 부제에는 완결된 결론을 쓴다. 표 셀은 간결한 명사형을 허용한다. 분량 축소는 제목 체계를 일괄 변경해도 된다는 뜻이 아니다.
- 표·계산 단계 중심으로 구성하고 억원 수치는 보통 두 자리로 표시한다. 반복 각주·검토 경과는 별도 근거 기록에 보존하고 사용자 삭제 문구를 자동 복원하지 않는다.
- 원본 차트의 디자인을 재사용해도 축 최대값·최소값·계열별 레이블 설정은 새 데이터에 맞춰 초기화한다. 값이 정확해도 잘린 축이나 남은 서식 때문에 그래프가 틀릴 수 있다.
- 편집 가능한 표·차트와 내장 데이터를 유지한다. 불필요한 원본 고객 정보는 본문뿐 아니라 노트·문서 제목 등 메타데이터에서도 제거한다.
- Pretendard 렌더링과 PDF 글꼴 포함 여부를 확인한다. LibreOffice에서 확인한 결과를 PowerPoint 실검수라고 하지 않는다.
- 카드의 본문 텍스트 상자 폭을 실제 배경 상자 안으로 제한한다. 전체 시각 검수 뒤 고친 장은 다시 렌더링해 확인한다.
- 관리양식의 계산식이 바뀌지 않는 편집이면 기존 검증을 유지하고 변경 부분을 확인한다. 미확보 고객 입력을0으로 채우지 않는다.

## 완료 기준

요청한 의사결정에 답하는 본문, 같은 결론을 반영한 요약, 근거로 되돌아갈 수 있는 계산·출처, 전체 렌더링한 납품 파일과 구체적인 후속 목록이 있어야 한다. 보고서 제작 완료와 실제 거래·신고 요건의 확정은 별도로 기록한다. 이미 승인된 제작·수정을 계속하기 위해 새로운 승인 절차를 만들지 않는다.
