# 페이지 흐름 설계

## 목적

설명자가 본문을 순서대로 넘기면서 고객의 질문에 답할 수 있게 한다. 각 페이지가 따로 완성되어 있어도, 앞의 분석에 필요한 전제를 뒤에서 먼저 가져와야 한다면 전체 구성은 미완성이다. 사용자가 검토에서 지적한 페이지 간 설명 순서 문제를 우선 검수 항목으로 반영한다.

## 1. 슬라이드 제작 전에 구성안을 작성한다

자료 파일의 순서가 아니라 독자의 질문과 이해에 필요한 순서를 기준으로 아래 표를 작성한다. 기존 대화에서 확정한 목적·독자·범위는 재질문하지 않는다.

| 순서 | 페이지 제목 | 핵심 메시지 한 문장 | 먼저 필요한 설명·앞 페이지 | 주요 근거·표현 | 다음으로 이어질 질문 |
|---|---|---|---|---|---|
| 본문 순서 | 다룰 주제 | 이 페이지에서 알게 되는 사실·판단 | 아직 소개되지 않은 전제가 있는지 | 자료·계산·표·구조도 등 | 다음 페이지가 왜 필요한지 |

- 먼저 질문과 답의 순서를 정하고, 필요한 근거를 그 흐름에 배치한다. 자료가 없는 결론은 만들어 넣지 않고 잠정 판단·미확인 사항으로 표시한다.
- 제목과 핵심 메시지만 위에서 아래로 읽는다. 새 용어·대상·대안·수치가 설명 없이 등장하면 먼저 필요한 설명의 위치를 조정한다.
- 다음 질문은 작성자의 연결 점검용이다. 보고서마다 질문형 제목이나 `다음 페이지에서는` 문구를 삽입하지 않는다. 장 마지막에는 다음 질문 대신 해당 장의 판단을 정리할 수 있다.
- 큰 목차만 보여주는 것으로 구성안을 대신하지 않는다. 새 보고서나 대규모 재구성에서는 전체 제작 전에 페이지별 제목과 메시지를 짧게 제시한다.
- 사용자가 구성안 검토 후 진행하라고 요청한 경우에만 답변을 기다린다. 그렇지 않으면 구성안을 공유하면서 근거 검토·제작을 이어간다. 이미 합의한 구성이나 일부 문구 수정 때문에 승인 절차를 새로 만들지 않는다.

## 2. 설명의 선후관계를 정한다

| 내용 | 배치 기준 |
|---|---|
| 회사·주주·자산 관계, 검토 대상과 제외 범위 | 해당 관계나 범위를 사용하는 분석 전에 최소한으로 설명 |
| 핵심 용어와 판단 기준 | 처음 실질적으로 사용하는 지점까지 소개. 제도 전체를 먼저 강의하지 않음 |
| 비교 대안과 공통 전제 | 대안별 계산·결과 비교 전에 정의 |
| 평가 방법과 주요 가정 | 평가 결과를 사용하는 본문 분석 전에 설명 |
| 전체 검토 결과 | 필요한 판단 기준을 제시한 뒤 요약. 주요 변화·예외의 해설로 연결 |
| 중요한 예외·미확인 조건 | 관련 판단이나 금액 가까이에 표시 |
| 권고안 | 본문에서 비교·분석한 결과와 조건을 받아 제시 |
| 상세 산식·전체 원자료·법령 전문 | 본문 이해에 필요한 요약을 남기고 별도 근거 기록에 보존. 부록은 전달 목적상 필요할 때만 사용 |

공통 전제는 한 번 정의하고 이후 페이지에서는 필요한 부분만 짧게 상기한다. 페이지마다 모든 배경을 반복하거나, 설명 순서를 맞추려고 불필요한 제도 소개 페이지를 늘리지 않는다. 독립된 검토 주제들은 장별로 완결되게 구성하고 서로의 인과관계를 만들지 않는다.

### 요약과 본문의 차이

핵심 요약은 결론을 먼저 제시해도 된다. 주요 조건과 판단 수준을 함께 적고, 상세 근거는 본문에서 설명한다. 본문 페이지 안에서도 판단 문장을 먼저 읽고 같은 페이지의 표·도식에서 근거를 확인하는 구성이 가능하다. 모든 결론을 보고서 맨 뒤로 옮기라는 뜻이 아니다.

본문의 흐름 오류는 앞의 주장을 이해하는 데 꼭 필요한 내용이 아직 나오지 않은 뒤쪽 페이지에만 있는 경우다. 상세 근거를 더 확인하려는 선택적 참조는 허용한다. 필수 전제가 부록에만 있으면 필요한 요약을 본문으로 가져온다.

### 순서 조정 예시

아래는 구조 설명용 가상 예시이며, 실제 고객의 결론·세액이나 모든 보고서에 적용할 고정 목차가 아니다.

- **Before:** 방안별 세부담 비교 → 주식 평가 결과 → 주주·자산 관계 → 비교 전제 → 권고안. 비교표를 설명하는 도중 뒤의 관계도와 전제를 먼저 보여줘야 한다.
- **After:** 검토 목적·범위 → 주주·자산 관계 → 비교 대안과 공통 전제 → 평가 방법·주요 가정 → 예비 평가 결과 → 방안별 세부담 비교와 차이 설명 → 권고안·확인 과제. 필요한 정보를 앞에서 받아 다음 분석으로 넘어간다.

표지·목차·핵심 요약은 이 본문 앞에 둘 수 있다. 간단한 업무에서는 목적·현황·전제 등을 한 페이지로 합칠 수 있으며, 위 항목 수를 페이지 수로 고정하지 않는다.

## 3. 흐름에 맞는 본문 표현을 고른다

| 설명 목적 | 권장 표현 | 독자가 바로 확인할 수 있어야 할 연결 |
|---|---|---|
| 대상·소유·거래 관계와 범위 | 관계도·구조도 | 어떤 주체·자산을 어떤 범위에서 검토하는지 |
| 요건 충족 여부 | 기준·회사 사실·판정의 행 또는 열 | 규정이나 기준에 실제 자료를 적용한 이유 |
| 대안·기간별 차이 | 같은 축의 비교표·차트 | 공통 전제, 달라진 값, 최종 비교 결과 |
| 다수 항목의 검토 결과 | 전체 결과표 후 주요 변화·예외 설명 | 어느 항목을 더 볼 필요가 있고 그 이유가 무엇인지 |
| 금액 산출과 해석 | 주요 입력·산식·결과를 연결한 표 | 결과가 어떤 전제와 계산에서 나왔는지 |
| 후속 조치 | 우선순위·이유·담당·확인자료 표 | 본문의 어떤 판단을 확정하거나 실행하기 위한 조치인지 |

표현 유형은 선택지다. 모든 페이지에 같은 수의 카드나 같은 칼럼을 강제하지 않는다. 회사에 대한 핵심 판단은 본문 상단에, 그 판단을 뒷받침하는 표·그림은 바로 아래에 둔다. 형식만으로 검토를 수행한 것처럼 보이게 만들지 않는다.

처음 합의하는 본문 유형이거나 시각적 불일치가 컸던 작업은 전체 분량을 확장하기 전에 대표 본문 1~2쪽을 먼저 만든다. 내용·정보량·배치를 실제 크기로 확인하고 가능한 경우 진행 상황으로 보여준다. 별도 요청 없이 필수 승인 단계로 만들지 않는다. 기존 CI·글꼴·표지·간지 체계는 유지한다.

## 4. 순서대로 설명하며 검수한다

1. **구성안 점검:** 제목과 핵심 메시지를 순서대로 읽고, 필요한 전제가 먼저 등장하는지 확인한다.
2. **완성 본문 점검:** 슬라이드 순서대로 실제 설명을 구성한다. 아직 소개하지 않은 뒤쪽 페이지를 먼저 열어야 이해되는 지점을 찾는다.
3. **수정 기록:** `문제 페이지 / 먼저 필요한 내용과 현재 위치 / 수정 방법`을 간단히 적는다. 예: `비교표 / 뒤쪽의 대안 정의 / 비교표 앞으로 정의 이동`.
4. **수정 선택:** 설명 블록 전체 이동, 필요한 최소 설명 추가, 핵심 표·가정의 본문 이동 중 적절한 방법을 고른다. 연결 문장만 덧붙여 구조 문제를 덮지 않는다.
5. **연결 재검수:** 목차·페이지 참조·장 제목·요약·권고안을 맞추고, 수정된 구간을 다시 순서대로 읽는다. 이후 시각 검수를 진행한다.

일부 페이지 수정에서는 해당 페이지의 앞뒤 연결과 영향을 받는 요약·참조를 점검한다. 구성 개선을 이유로 무관한 승인 문구·디자인을 전면 재작성하지 않는다.
